# e4steam 0.3.0 implementation roadmap

This Draft PR is a complete, disabled-by-default foundation rather than the
entire platform described by the 0.3.0 specification. Existing friends/invite
behavior remains the only active user flow. No incomplete security-sensitive
feature below is registered or advertised at runtime.

## Completed in the foundation PR

- stable Steam-derived offline Minecraft identity for authenticated bridges;
- bounded, deduplicated and worker-generation-safe RESET retry lifecycle;
- owner-controlled native cache with type/owner/hash/link checks and
  process-safe publication serialization;
- loader-independent Java 8 API `0.1.0`, testkit, example addon, Javadocs,
  purity audit and public-surface baseline;
- safe addon metadata, capabilities, runtime snapshots, observational events,
  named scheduler contracts, typed errors and resource ownership;
- privacy, threading, lifecycle, future-addon and unsupported-platform design
  documentation;
- read-only Windows/Linux CI with immutable action revisions.

## Follow-up PR sequence

1. Wire loader-native addon discovery, deterministic dependency validation,
   lifecycle teardown and API implementation adapters. Do not scan arbitrary
   JAR files.
2. Add bounded session, identity, access-policy and lobby services. Custom
   policy may only add restrictions after mandatory core admission gates.
3. Add authenticated namespaced addon-channel negotiation, codecs, fairness,
   fuzz/property tests and an opt-in bounded UDP provider service.
4. Add loader adapters for UI contributions, commands, localized text,
   configuration, scoped storage, diagnostics and allowlisted world-setting
   proposals.
5. Add only neutral contracts for future Public Worlds, Modpack Sync, Offline
   Skins and World Settings addons; keep their real behavior out of core.
6. Audit official Steam client/GameServer native provenance before any macOS
   work. Implement and smoke-test Intel and native Apple Silicon separately;
   until then macOS remains unsupported.
7. Implement dedicated mode only after a real Steam GameServer backend, ticket
   lifecycle, fail-closed vanilla ingress guard, headless loader isolation and
   two-client tests exist. Until then dedicated mode remains unsupported.
8. Create isolated retro toolchains for exact Forge targets 1.6.4, 1.7.10,
   1.8.9, 1.9.4, 1.10.2, 1.11.2, 1.12.2, 1.13.2, 1.14.4, 1.15.2 and 1.16.5,
   plus separate Fabric targets covering 1.14.4 through 1.16.5. Do not ship a
   generic retro JAR or other retro loaders.
9. Run the modern manual host/join/reconnect matrix, Linux native-cache tests
   with symlink support, macOS smoke matrix, dedicated two-client matrix and
   every retro launch/host/join test before changing any support claim.

The current upstream audit and exact e4mc-retro revisions are recorded in
[`RETRO_PORTING.md`](RETRO_PORTING.md). No upstream source was copied by this
foundation PR.
