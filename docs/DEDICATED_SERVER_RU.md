# Выделенные серверы

[English version](DEDICATED_SERVER.md)

Эта страница объясняет принцип работы. Для установки используйте отдельную
[пошаговую инструкцию](DEDICATED_DEPLOYMENT_RU.md).

## Коротко

- Установите обычный JAR e4steam, подходящий версии Minecraft и загрузчику
  сервера. Отдельного серверного JAR нет.
- Привяжите Minecraft к `127.0.0.1` и включите e4steam в
  `config/e4steam-dedicated.toml`.
- Запустите сервер обычным способом. Личный клиент Steam на серверном ПК не
  нужен.
- Дождитесь строки `e4steam dedicated address: d-...steam`.
- Передайте адрес разрешённому игроку. Он вставляет его в обычное поле адреса
  сервера Minecraft, а на его компьютере должен быть запущен Steam.

Сервер анонимно входит в Steam GameServer для App ID 480. Личный Steam-аккаунт,
список друзей, оверлей и GSLT ему не нужны.

## Поддерживаемые платформы

Основная серверная платформа — Windows x64. Авторизованный вход вручную
проверен на NeoForge 1.21.1, Fabric 26.2 и Forge 1.12.2. В JAR также есть код и
библиотеки для Linux и macOS, но полная ручная матрица этих систем ещё не
закончена, поэтому они остаются экспериментальными.

Точные результаты перечислены в [COMPATIBILITY.md](../COMPATIBILITY.md).
Успешная сборка JAR не означает проверенное подключение игрока.

## Как проходит подключение

```text
Игрок вводит d-...steam
        |
        v
Steam Networking Messages / ретранслятор Valve
        |
        v
проверка поколения сервера и личности Steam
        |
        v
проверка лимита, бана и allowlist
        |
        v
короткоживущий авторизованный локальный мост
        |
        v
Minecraft-сервер на 127.0.0.1
```

Minecraft не открывается напрямую в локальную сеть или интернет. До
Minecraft-login доходит только соединение, для которого e4steam заранее создал
запись после проверки Steam. У обычного TCP-клиента, даже локального, такой
записи нет, поэтому вход отклоняется.

## Что такое адрес `d-...steam`

В адресе указаны анонимный Steam GameServer и текущее поколение runtime. Это не
билет авторизации и не способ обойти allowlist, бан, лимит или проверку версии
протокола.

Адрес всё равно относится к действующей сессии, поэтому передавайте его только
нужным игрокам. После перезапуска backend создаётся новое поколение, и старый
адрес перестаёт использоваться.

e4steam не публикует сервер в общем Steam Server Browser. В ядре нет публичного
каталога серверов или провайдера публикации.

## Состояния запуска

```text
CONFIG_VALIDATED
  -> NATIVES_READY
  -> STEAM_INITIALIZING
  -> STEAM_LOGGING_ON
  -> TRANSPORT_READY
  -> MINECRAFT_READY
  -> ACCEPTING
  -> DRAINING
  -> STOPPED
```

При ошибке появляется `FAILED`. Адрес печатается только в состоянии
`ACCEPTING`, когда готовы и Steam-транспорт, и вход Minecraft.

| Состояние | Значение |
| --- | --- |
| `CONFIG_VALIDATED` | Конфиг и `server.properties` прошли строгую проверку |
| `NATIVES_READY` | Нужные библиотеки Steam выбраны и загружены |
| `STEAM_LOGGING_ON` | Идёт анонимный вход GameServer |
| `TRANSPORT_READY` | Steam готов принимать трафик e4steam |
| `MINECRAFT_READY` | Локальный listener и login-hooks Minecraft готовы |
| `ACCEPTING` | Адрес действителен, разрешённые игроки могут входить |
| `DRAINING` | Новые входы закрыты, существующие мосты завершаются |
| `FAILED` | Запуск или работа остановились из-за записанной ошибки |

## Режимы доступа

- `PRIVATE` и `WHITELIST` требуют наличия игрока в allowlist из конфига или
  runtime-хранилища.
- `UNLISTED` разрешает попытку входа любому совместимому и авторизованному
  пользователю Steam с актуальным адресом. Лимит и баны продолжают работать.
- `CUSTOM` предназначен для отдельного provider-аддона. Без такого провайдера
  ядро отклоняет режим.

Личный список друзей хоста здесь не используется: у выделенного сервера нет
личного Steam-аккаунта.

## Загрузчики и старые версии

Современные JAR Fabric/Quilt, Forge и NeoForge содержат headless-entrypoint.
Retro JAR Forge `1.7.x-1.16.x` и Fabric `1.14.x-1.16.x` также содержат Java 8
bootstrap для выделенного сервера.

Retro-серверы передают обычный Minecraft-трафик через ту же проверенную Steam-
границу. В них нет Addon API, согласования addon-каналов и современного дерева
консольных команд. Их allowlist нужно настроить до запуска.

## Addon API

На современном сервере `DedicatedServerService` доступен через
`context.api().dedicatedServers()`.

Capability `DEDICATED_OBSERVE` позволяет читать состояние, готовность,
безопасный снимок конфига, режим доступа, число игроков и лимит.

`DEDICATED_ADMIN` разрешает `drain(reasonCode)`. Drain закрывает новые входы
через e4steam, но не сохраняет мир и не завершает Minecraft.

`DEDICATED_PUBLICATION_PROPOSE` разрешает предложить внешнюю публикацию, однако
ядро всё равно требует установленный доверенный provider и разрешение в
конфиге. В core e4steam 0.3.1 такого провайдера нет, поэтому возвращается
`public-worlds-addon-required`.

API не выдаёт auth tickets, GSLT, закрытые поля адреса, native handles и сырые
Steam-пакеты. Подробности есть в [документации Addon API](ADDON_API_RU.md).
